# OctoAcme Project Management Documentation

Welcome to the OctoAcme project management guide. This documentation brings together the processes and practices used to plan, deliver, release, and learn from cross-functional projects.

## Quick Overview

OctoAcme uses a structured, iterative approach that keeps teams focused on customer value while making ownership, progress, and decisions visible.

### Key Principles

- **Customer-first:** Prioritize customer value and usability.
- **Iterative delivery:** Deliver small, testable increments and learn from them.
- **Clear ownership:** Give every project a named Project Manager and Product Manager/Product Lead.
- **Data-informed decisions:** Measure outcomes and adapt based on evidence.
- **Psychological safety:** Encourage candid feedback, shared learning, and blameless improvement.

### Core Roles

- **Project Manager (PM):** Coordinates delivery, schedules, risks, dependencies, and communications.
- **Product Manager (PdM):** Defines outcomes, prioritizes the backlog, and measures success.
- **Developers:** Design, build, and test features; collaborate on implementation and testability.
- **QA/Testing:** Validates quality against acceptance criteria and helps surface defects.
- **Stakeholders:** Provide context, input, and approvals at appropriate decision points.

## Project Lifecycle

Projects move through five connected phases:

1. **Initiation:** Define the problem and intended outcomes, align stakeholders, and establish an initial project one-pager.
2. **Planning:** Shape the scope, milestones, resources, dependencies, risks, and shippable increments.
3. **Execution:** Build, test, review, and iterate while tracking progress and addressing blockers.
4. **Release:** Verify release readiness, deploy, monitor, communicate, and have a rollback plan.
5. **Close & Retrospective:** Capture results and lessons, then turn learning into actionable improvements.

## Getting Started for New Team Members

1. Read the [Project Management Overview](octoacme-project-management-overview.md) to learn the framework and lifecycle.
2. Review [Roles and Personas](octoacme-roles-and-personas.md) to understand how you and your collaborators contribute.
3. Ask your Project Manager or Product Manager for the current project one-pager, roadmap, backlog, acceptance criteria, and team communication channels.
4. Read the guide for the phase your project is in, and check the project’s source of truth for current status, decisions, and next steps.

## Communication Cadence

The standard cadence is a weekly Project Manager–Product Manager sync, twice-weekly delivery-team standups (or as agreed by the team), monthly stakeholder updates, and ad-hoc escalations as needed. Teams can adapt meeting frequency to their context; communicate significant risks, blockers, and decisions promptly.
